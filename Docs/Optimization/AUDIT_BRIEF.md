# Optimization audit brief

Project: `/Users/kyle-anthonyhay/Documents/MY FILES/CODE/Games/Sovereign-Realms/VoxelLab` (ROOT), an Unreal Engine 5.8 voxel RTS on macOS (Apple Silicon, Metal). Read `ROOT/README.md` first.

Goal: a full audit of the game for OPTIMIZATION opportunities — frame rate (CPU game thread, render thread, GPU), memory, load/startup time, package size, and the per-frame cost of systems. Find concrete, evidence-backed findings; do NOT change any code or assets (findings only). Three auditors (GPT 6.1 Sol, Opus 5.5, Fable 5.2) work independently; an Opus agent will later merge the findings and delegate the fixes.

## What to look at (non-exhaustive)
- Rendering: Lumen settings (`Config/DefaultEngine.ini`, the level's post-process; README notes say Lumen + fog dominate), shadows (sun shadow distance on L_Realm raised to 1,100 m), volumetric fog, custom-depth/silhouette pass (now all units incl. enemies write custom depth), translucency (dust, flash overlay), material complexity (`M_Voxel`, `M_VoxUnit`, `M_VoxSway` WPO wind on plants and cloth, `M_VoxWater`), draw calls (characters are ~35-38 static-mesh parts EACH: King/troops/spy/builder; troops 50-60k triangles each), Nanite (off), HISM forest (`AVLForest`, LODs, cull distances), terrain tiles (L_Realm 1.9M faces, L_Highlands 3.7M), mesh face counts (trees 30-100k, buildings 55-70k), lights (one point light per lantern: dozens), the minimap capture, the title-screen backdrop.
- Game-thread CPU: per-tick work in `Source/VoxelLab/` — `AVLKing::Tick/Animate/UpdateCape/UpdateSword` per unit (procedural animation of ~35 parts + 20-panel cape per unit), `VLBattle` (targeting/acquisition loops, O(n²) scans, TActorIterator use per frame), `VLCommand` (formation, AutoSteer separation loop iterating all units per unit), `VLGrid` (path grid build 1.5–2.4 s at match start, A*, RebuildArea), `VLEnemyAI`/`VLAIWorld`/`VLAISquads` (influence map, decisions), `VLArrow` (pooled arrows, traces per frame), `VLHUD*` (Canvas drawing each frame, world projections per unit), `VLFootDust`, `VLAmbience`, `VLForest`, audio (sound spawning, shuffle), `GetAllActorsOfClass`/`TActorIterator` hot paths, string/FName building per frame, allocations per frame, logging in hot paths.
- Memory/load: texture settings, mesh LODs, cooked size (package is ~1.5 GB; what dominates?), maps' instance counts, streaming, music WAVs (8 tracks ~45 MB each as WAV — compression settings?), shader permutations.
- Scalability: settings exposed to the player (frame cap, interface scale exist), dynamic resolution / TSR / screen percentage, LOD bias, per-quality presets.

## How
- Static review of the code, configs, build scripts (`Tools/ue/*.py`, `Tools/blender/*`), and assets (sizes in `Content/`, `SourceArt/Meshes/*.json` face counts).
- Optional measurement: you MAY run the editor to profile (`stat unit`, `stat gpu`, `stat scenerendering`, `stat game`, `profilegpu`, `stat startfile`/Insights, `obj list`, `memreport`), using the tools in README (`Tools/editor.sh`, `Tools/pie.py`, `vl.*` commands such as `vl.StartMatch`, `vl.AIvsAI 1`, `vl.TimeScale`). Other auditors may also want the editor: acquire the lock with `mkdir "ROOT/Saved/editor.lock"` (if it exists, wait in a single Bash polling loop: `for i in $(seq 1 60); do mkdir ... && break; sleep 30; done` — do not end your turn while waiting), keep sessions SHORT (≤ 15 min), release with `sh Tools/editor.sh quit; rmdir "ROOT/Saved/editor.lock"`. Music is off by default; keep it off. Do not edit project files.

## Output
Write your findings to `ROOT/Docs/Optimization/findings_<your-model>.md` (e.g. `findings_gpt61sol.md`, `findings_opus55.md`, `findings_fable52.md`). For each finding: ID, area, evidence (file:line, numbers measured or computed), estimated impact (high/medium/low, with reasoning: ms or MB if possible), effort, risk (visual/behaviour change?), and a concrete recommended fix. Order by impact/effort. Include a short summary at the top and a "measurements" section if you profiled. Do not modify anything else.
